# Flowers Batum Flower — Telegram Mini App

Полностью рабочий прототип: витрина для покупателей + панель для персонала
(каталог, склад с приходом/списанием, заказы), под запуск как Telegram Mini App.

## Что уже сделано и правда проверено

Я собирал это в изолированной песочнице без доступа в интернет, поэтому
осознанно выбрал стек, который можно реально запустить и протестировать
локально, а не просто написать «на веру»:

- **Backend — Flask + SQLite**, без сторонних пакетов кроме самого Flask
  (авторизация Telegram — это HMAC, из стандартной библиотеки `hmac`/`hashlib`;
  уведомления — через `urllib`, без SDK).
- **Frontend — обычные HTML/CSS/JS** (ES-модули, без сборки и без npm) —
  Telegram Mini App это просто веб-страница, React тут не обязателен, а без
  доступа к npm я всё равно не смог бы поставить и проверить его пакеты.

Что реально прогонялось и проходило в песочнице (см. `backend/test_flow.py`
и `backend/test_bot.py`):
- покупатель делает заказ → склад автоматически списывается по «рецепту»
  букета;
- персонал видит новый заказ, меняет статус, статус уходит клиенту;
- приход и списание на складе меняют остаток правильно;
- доступ в админку закрыт для не-персонала (проверено, что чужой Telegram ID
  получает 403);
- запрос без подписи Telegram вообще отклоняется (401);
- бот на `/start` и `/admin` шлёт правильные кнопки запуска Mini App.

Чего я **не** мог проверить отсюда: как это реально выглядит и ощущается в
самом Telegram, и работу с настоящим `BOT_TOKEN`/настоящим сервером — для
этого нужен интернет и живой бот, которых у меня в песочнице нет. Логику и
данные я проверил насколько мог; внешний вид стоит спокойно посмотреть
глазами после деплоя.

## Структура проекта

```
backend/
  app.py          — Flask: отдаёт API и статику фронтенда
  models.py       — схема SQLite
  auth.py         — проверка подписи Telegram initData
  seed.py         — тестовые данные (под ваш реальный ассортимент)
  bot.py          — отдельный процесс: бот на long polling (/start, /admin)
  test_flow.py    — сквозной тест магазина (можно перезапускать)
  test_bot.py     — тест маршрутизации бота
  requirements.txt
frontend/
  customer/       — витрина покупателя
  admin/          — панель персонала
  shared/         — общие стили и обёртка над Telegram WebApp SDK
  img/            — картинки (включая заглушку фото букета)
```

## Как запустить локально

```bash
cd backend
pip install -r requirements.txt
python3 seed.py        # создаёт shop.db с тестовыми данными
python3 app.py          # http://localhost:5000
```

Откройте `http://localhost:5000` — витрина. `http://localhost:5000/admin` —
админка (снаружи Telegram покажет «доступ только для сотрудников» — это
ожидаемо и правильно, так и должно быть: см. ниже, как проверить админку
локально).

**Проверить админку без реального Telegram.** Настоящую подпись без
Telegram не получить, но её можно сгенерировать так же, как это делает сам
Telegram — локально, на сервере:

```bash
cd backend
python3 -c "
from auth import sign_init_data
import json, time
fields = {'auth_date': str(int(time.time())), 'user': json.dumps({'id': 111111111, 'first_name': 'Владелец'})}
print(sign_init_data(fields, 'LOCAL_DEV_TOKEN'))
"
```
(111111111 — id владельца из `seed.py`; BOT_TOKEN по умолчанию — `LOCAL_DEV_TOKEN`, пока вы не задали свой). Полученную строку подставьте в адрес:
`http://localhost:5000/admin?dev_init_data=ВСТАВЬТЕ_СЮДА`. Секрет при этом
нигде не попадает в код фронтенда — только в адресную строку у вас на
компьютере.

## Как задеплоить по-настоящему

⚠️ **Backend и frontend — это ОДИН сервис, не два.** `app.py` уже сам
отдаёт и API, и HTML/CSS/JS (customer и admin). Если развернуть их как два
разных сервиса (два разных адреса), браузер не найдёт часть файлов и
запросов — получится «открывается, но ничего не грузится». На хостинге
нужен ровно один сервис — его вы получаете, разворачивая папку `backend/`
(она сама подтягивает `frontend/` через относительный путь).

1. **Получите BOT_TOKEN.** В Telegram напишите @BotFather → `/newbot` →
   следуйте подсказкам → он пришлёт токен.
2. **Разместите backend на HTTPS-хостинге** (Railway, Render,
   PythonAnywhere, свой VPS — что угодно, что держит процесс Python и даёт
   HTTPS-адрес). Команда запуска: `python3 app.py` — она уже читает порт из
   переменной окружения `PORT`, которую подставляет хостинг.
3. **Задайте переменные окружения** на хостинге:
   - `BOT_TOKEN` — из шага 1;
   - `OWNER_TELEGRAM_ID` — ваш личный Telegram ID (узнать — написать боту
     @userinfobot, он пришлёт ID в ответ). После этого при следующем
     запуске вы автоматически появитесь в админке как владелец — руками в
     базу данных лезть не нужно;
   - при желании `OWNER_NAME`, `SHOP_NAME`, `SHOP_ADDRESS`.
4. **В @BotFather** пропишите Mini App: `/mybots` → ваш бот → Bot Settings
   → Menu Button → укажите HTTPS-адрес вашего сервиса из шага 2 (тот же
   адрес и для витрины, и для админки — админка живёт по тому же адресу с
   `/admin` на конце).
5. Откройте бота в Telegram, нажмите кнопку меню — должна открыться
   витрина. Админка — по тому же адресу + `/admin`.
6. **Добавление ещё сотрудников** (не только вас): пока это делается только
   напрямую в базе (через `staff`, по аналогии с `bootstrap()` в `app.py`) —
   если понадобится, дайте знать, добавлю для этого кнопку в самой админке,
   это несложно.
7. Замените тестовые товары `seed.py` на настоящие — их не нужно трогать
   руками: `seed.py` не запускается автоматически при деплое, а сами товары
   и позиции склада можно сразу добавлять через кнопки в самой админке
   («+ Товар», «+ Позиция»).
8. Уведомления (новый заказ, смена статуса) и команды `/start`/`/admin` шлёт
   `bot.py` — это отдельный процесс, его нужно запускать и держать
   работающим отдельно от `app.py` (`python3 bot.py`, переменные `BOT_TOKEN`
   и `APP_URL`). Без него магазин и админка всё равно работают — просто не
   будет уведомлений и кнопки быстрого запуска из чата с ботом.

## Чего пока нет (осознанно, чтобы уложиться в разумный объём)

- Переключателя языка на английский/грузинский в интерфейсе — сама структура
  (тексты в JS, а не зашиты в HTML) готова к этому, но переключатель не
  сделан.
- Онлайн-оплаты через Telegram Payments — на старте только «наличные / карта
  курьеру / перевод»; с оплатой картой в Telegram Payments нужно отдельно
  проверять, какой провайдер сейчас работает с Грузией.
- Отчётности (сводка продаж, топ товаров) и программы лояльности/промокодов.
- Переключателя между двумя точками продаж в самом интерфейсе — поле
  `location_id` есть во всех таблицах, но сейчас everything захардкожено на
  точку №1 (Parnavaza St); когда откроется Batumi View, понадобится либо
  простой селектор точки, либо два отдельных бота.

## Как пользоваться админкой

Внизу экрана три вкладки:
- **Заказы** — список заказов, фильтр по статусу сверху, у каждого заказа —
  выпадающий список сменить статус (клиенту сразу уйдёт уведомление, если
  запущен `bot.py`). Тап по карточке — полная информация по заказу.
- **Каталог** — кнопка «+ Товар» вверху добавляет новый букет/товар (фото,
  название, категория, варианты размера и цены). ✎ — редактировать, 🗑 —
  удалить.
- **Склад** — кнопка «+ Позиция» добавляет новый вид цветов на склад
  (название, ед. измерения, начальный остаток). У каждой позиции — кнопки
  «+ приход» (когда привезли новую партию) и «− списание» (брак, увядшие).
  Если у товара в каталоге задан «рецепт» (какие цветы и сколько уходит на
  букет), списание при продаже происходит само.

Если вместо этого видите «доступ только для сотрудников» — значит
`OWNER_TELEGRAM_ID` ещё не задан на хостинге или сервис не перезапускался
после того, как вы его добавили.

## Валюта

Цены сейчас в лари (₾) — самая логичная валюта для бизнеса в Грузии. Если
нужно показывать в другой — символ задан в одном месте (`money()` в
`frontend/customer/app.js` и `frontend/admin/app.js`), поменять легко.
